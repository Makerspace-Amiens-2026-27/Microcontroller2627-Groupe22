# TD microcontrôleur : port série, modules de la mallette et capteurs

**Carte :** Seeed Studio XIAO ESP32S3 Plus · **Outils :** VSCode + PlatformIO, extension TelePlot

{: .warning }

> ne supportent pas plus de 3,3 V.

## Fait

### 1. Port série et TelePlot

On a d'abord envoyé un sinus sur le port série pour vérifier la communication entre la
carte et le PC. Sur la XIAO, `Serial` passe directement par l'USB natif de l'ESP32-S3
(pas de puce USB-série), donc pas de driver à installer. On a utilisé
**Upload and Monitor** pour que le moniteur se rouvre tout seul après le téléversement.

Ensuite on a affiché les valeurs en courbes avec l'extension **TelePlot** : il suffit
de mettre un `>` devant le nom de la donnée pour qu'elle soit tracée. Code final avec
deux courbes :

```cpp
#include <Arduino.h>

float i = 0;

void teleplot(const char* label, float value)
{
  Serial.printf(">%s:%.3f\n", label, value);
}

void setup()
{
  Serial.begin(115200);
  delay(1500);   // USB natif : laisse le temps au PC de rouvrir le port
}

void loop()
{
  i += 0.1;
  teleplot("sin", sin(i));
  teleplot("cos", cos(i));
  delay(10);
}
```

**Résultat :** TelePlot connecté sur COM3 à 115200 bauds, environ 200 valeurs/s reçues
(2 valeurs toutes les 10 ms). Les courbes sin et cos sont bien décalées d'un quart de
période (π/2).

Premier test avec **Upload and Monitor** : les valeurs du sinus défilent dans le terminal.

### 2. Modules de la mallette

On a testé chaque module séparément sur breadboard, avec les broches de la future carte
de la console.

| Module | Broche du module | Broche XIAO |
|---|---|---|
| Bouton | `S` | D5 |
| Joystick | `VRx` / `VRy` / `SW` | D0 / D1 / D2 |
| Buzzer | `S` | D3 (seulement sur breadboard) |
| Tous | `VCC` / `GND` | 3V3 / GND |

Les broches sont regroupées dans `include/config.h` :

```cpp
#pragma once

#include <Arduino.h>

constexpr int PIN_BUTTON          = D5;
constexpr int PIN_JOYSTICK_X      = D0;
constexpr int PIN_JOYSTICK_Y      = D1;
constexpr int PIN_JOYSTICK_SELECT = D2;
constexpr int PIN_BUZZER          = D3;   // seulement sur breadboard

constexpr int PIN_TFT_RESET = D7;
constexpr int PIN_TFT_DC    = D8;
constexpr int PIN_TFT_SCK   = D9;
constexpr int PIN_TFT_MOSI  = D10;
constexpr int PIN_TFT_CS    = -1;   // CS relié à GND : pas de broche
```

#### Bouton : lire son niveau

On a d'abord affiché le niveau du bouton au moniteur série. Résultat : **HIGH quand il
est relâché, LOW quand on appuie**.

```cpp
#include "config.h"

void setup() {
    Serial.begin(115200);
    delay(1500);
    pinMode(PIN_BUTTON, INPUT_PULLUP);
}

void loop() {
    Serial.println(digitalRead(PIN_BUTTON) == HIGH ? "HIGH" : "LOW");
    delay(200);  // programme de test : on ralentit l'affichage
}
```

#### Bouton : un seul événement par appui

Ensuite on a codé une détection de front avec un anti-rebond de 30 ms, sans `delay()`,
pour avoir un seul événement par appui :

```cpp
#include "config.h"

constexpr int PRESSED_LEVEL = LOW;           // niveau lu quand on appuie
constexpr unsigned long DEBOUNCE_MS = 30;

struct Button {
    int pin;
    int stableLevel;              // dernier niveau confirmé
    int lastRead;                 // dernière lecture brute
    unsigned long lastChangeMs;   // date du dernier mouvement du signal
};

Button button = {PIN_BUTTON, !PRESSED_LEVEL, !PRESSED_LEVEL, 0};

// Renvoie true une seule fois par appui, au moment où il est confirmé
bool justPressed(Button& b) {
    int level = digitalRead(b.pin);
    if (level != b.lastRead) {
        b.lastRead = level;
        b.lastChangeMs = millis();
    }
    if (millis() - b.lastChangeMs > DEBOUNCE_MS && level != b.stableLevel) {
        b.stableLevel = level;
        return level == PRESSED_LEVEL;
    }
    return false;
}

void setup() {
    Serial.begin(115200);
    delay(1500);
    pinMode(PIN_BUTTON, INPUT_PULLUP);
}

void loop() {
    static int count = 0;
    if (justPressed(button)) {
        count++;
        Serial.printf("Appui n°%d\n", count);
    }
}
```

#### Joystick : valeurs brutes

Les deux axes sont des potentiomètres lus par l'ADC 12 bits (0 à 4095), et `SW` est un
bouton relié à GND.

```cpp
#include "config.h"

void setup() {
    Serial.begin(115200);
    delay(1500);
    pinMode(PIN_JOYSTICK_SELECT, INPUT_PULLUP);
    analogReadResolution(12);  // lectures entre 0 et 4095
}

void loop() {
    int x = analogRead(PIN_JOYSTICK_X);
    int y = analogRead(PIN_JOYSTICK_Y);
    bool pressed = digitalRead(PIN_JOYSTICK_SELECT) == LOW;

    Serial.printf("x=%d y=%d select=%d\n", x, y, pressed);
    delay(100);
}
```

**Résultat :** au repos, x vaut environ 1930 et y environ 1950, donc pas pile 2048. Les
deux axes atteignent bien 0 et 4095 aux butées.

#### Joystick : calibration et normalisation

Comme le centre n'est pas 2048, on le calibre au démarrage (moyenne de 16 lectures),
on ajoute une zone morte de 300 et on ramène la valeur entre -1 et +1 :

$$
x_{\text{norm}} = \frac{\text{brut} - \text{centre}}{\text{course}}
\quad \text{avec} \quad
\text{course} =
\begin{cases}
4095 - \text{centre} & \text{si brut} > \text{centre} \\
\text{centre} & \text{sinon}
\end{cases}
$$

```cpp
#include "config.h"

constexpr int JOYSTICK_DEADZONE = 300;
int joystickCenterX = 2048;

void calibrateJoystick() {
    long sum = 0;
    for (int i = 0; i < 16; i++) {
        sum += analogRead(PIN_JOYSTICK_X);
        delay(2);
    }
    joystickCenterX = sum / 16;
}

// Convertit une lecture brute (0..4095) en valeur entre -1.0 et +1.0
float normalizeJoystick(int raw, int center) {
    int offset = raw - center;
    if (abs(offset) < JOYSTICK_DEADZONE) {
        return 0.0f;
    }
    int range = (offset > 0) ? (4095 - center) : center;
    return constrain((float)offset / range, -1.0f, 1.0f);
}

void setup() {
    Serial.begin(115200);
    delay(1500);
    analogReadResolution(12);
    calibrateJoystick();
    Serial.printf("Centre calibre : %d\n", joystickCenterX);
}

void loop() {
    float x = normalizeJoystick(analogRead(PIN_JOYSTICK_X), joystickCenterX);
    Serial.printf("x=%.2f\n", x);
    delay(100);
}
```

**Résultat :** 0.00 au repos, -1.00 d'un côté, +1.00 de l'autre, avec les valeurs
intermédiaires entre les deux.

#### Buzzer

Le programme joue une gamme avec `tone()` (buzzer passif), puis met la broche à HIGH
pendant 500 ms (buzzer actif). Ça permet de savoir quel type de buzzer on a :

```cpp
#include "config.h"

void setup() {
    pinMode(PIN_BUZZER, OUTPUT);

    // Test 1 : buzzer passif, gamme do-ré-mi-fa-sol
    const int notes[] = {262, 294, 330, 349, 392};  // fréquences en Hz
    for (int note : notes) {
        tone(PIN_BUZZER, note, 200);
        delay(250);
    }
    delay(1000);

    // Test 2 : buzzer actif, bip d'une demi-seconde
    digitalWrite(PIN_BUZZER, HIGH);
    delay(500);
    digitalWrite(PIN_BUZZER, LOW);
}

void loop() {}
```

### 3. Capteurs supplémentaires

Pour ces trois modules, on a utilisé **D4** et **D6**, les deux broches que la mallette
laisse libres : pas besoin de débrancher le reste du montage.

#### Capteur de température et d'humidité (KY-015, DHT11)

| Module | Broche XIAO |
|---|---|
| `S` | D4 |
| milieu | 3V3 |
| `-` | GND |

La résistance de tirage de 10 kΩ est déjà sur le module. Le DHT11 utilise un seul fil
de données avec son propre protocole, d'où la bibliothèque Adafruit.

```cpp
#include <Arduino.h>
#include <DHT.h>

constexpr int PIN_DHT = D4;

DHT dht(PIN_DHT, DHT11);

void setup() {
    Serial.begin(115200);
    delay(1500);
    dht.begin();
}

void loop() {
    float humidity = dht.readHumidity();
    float temperature = dht.readTemperature();   // en °C

    if (isnan(humidity) || isnan(temperature)) {
        Serial.println("Erreur de lecture du DHT11");
    } else {
        Serial.printf(">temperature:%.1f\n", temperature);
        Serial.printf(">humidite:%.0f\n", humidity);
    }
    delay(2000);   // le DHT11 ne donne pas plus d'une mesure par seconde
}
```

**Résultat :** entre 23,2 et 23,7 °C, et entre 63 et 65 % d'humidité dans la salle.

#### Capteur de son (KY-037 « big sound »)

| Module | Broche XIAO |
|---|---|
| `AO` (analogique) | D4 |
| `G` | GND |
| `+` | 3V3 |
| `DO` (numérique) | D6 |

`AO` donne le signal du micro et `DO` change d'état quand le son dépasse un seuil,
réglé avec le potentiomètre bleu. Comme le son est une onde, une seule lecture ne veut
rien dire : on mesure l'écart entre le min et le max sur 50 ms (crête à crête).

```cpp
#include <Arduino.h>

constexpr int PIN_SOUND_AO = D4;
constexpr int PIN_SOUND_DO = D6;
constexpr uint32_t WINDOW_MS = 50;   // fenêtre de mesure

void setup() {
    Serial.begin(115200);
    delay(1500);
    pinMode(PIN_SOUND_DO, INPUT);
    analogReadResolution(12);
}

void loop() {
    int minValue = 4095, maxValue = 0;
    int samples = 0, highCount = 0;
    uint32_t start = millis();

    while (millis() - start < WINDOW_MS) {
        int v = analogRead(PIN_SOUND_AO);
        if (v < minValue) minValue = v;
        if (v > maxValue) maxValue = v;
        if (digitalRead(PIN_SOUND_DO) == HIGH) highCount++;
        samples++;
    }

    Serial.printf(">volume:%d\n", maxValue - minValue);      // crête à crête
    Serial.printf(">AO_moyen:%d\n", (maxValue + minValue) / 2);
    Serial.printf(">DO_pourcent_HIGH:%d\n", highCount * 100 / samples);
}
```

**Résultat :** le volume passe d'environ 150 en silence à près de 960 sur un bruit
fort. `DO` reste à HIGH en silence (100 %) et passe brièvement à LOW quand le son
dépasse le seuil (97 % sur un bruit fort). `AO_moyen` reste assez bas au calme
(entre 60 et 300 environ), ce qui veut dire que le potentiomètre est proche d'une
butée : on pourrait le recentrer pour avoir plus de marge.

#### Laser (KY-008) commandé par le bouton

| Module | Broche XIAO |
|---|---|
| Laser `S` | D6 |
| Laser milieu | non connecté |
| Laser `-` | GND |
| Bouton `S` | D5 |
| Bouton milieu (`+`) | 3V3 |
| Bouton `-` | GND |

C'est la broche `S` qui alimente la diode laser, à travers la résistance déjà présente
sur le module. Le laser se commande donc comme une LED (HIGH = allumé).

{: .warning }
> Ne jamais regarder le faisceau ni le pointer vers quelqu'un.

```cpp
#include <Arduino.h>

constexpr int PIN_LASER  = D6;
constexpr int PIN_BUTTON = D5;
constexpr int PRESSED_LEVEL = LOW;

void setup() {
    pinMode(PIN_LASER, OUTPUT);
    pinMode(PIN_BUTTON, INPUT_PULLUP);

    // Test 1 : 5 clignotements
    for (int i = 0; i < 5; i++) {
        digitalWrite(PIN_LASER, HIGH);
        delay(300);
        digitalWrite(PIN_LASER, LOW);
        delay(300);
    }
}

void loop() {
    // Test 2 : laser allumé tant que le bouton est appuyé
    digitalWrite(PIN_LASER, digitalRead(PIN_BUTTON) == PRESSED_LEVEL ? HIGH : LOW);
}
```

## Pourquoi

- **Alimentation en 3V3 partout** : l'ESP32-S3 ne supporte pas 5 V sur ses entrées.
  Un module prévu pour 5 V marche presque toujours en 3,3 V, l'inverse peut détruire
  la carte.
- **`delay(1500)` après `Serial.begin()`** : avec l'USB natif, le port disparaît à
  chaque reset, et sans ce délai on perd les premiers messages.
- **`const char*` plutôt que `String`** dans la fonction TelePlot : un `String`
  réserve de la mémoire à chaque appel et peut fragmenter le tas.
- **`INPUT_PULLUP` sur le bouton** : évite une entrée flottante si le module n'a pas
  sa propre résistance de tirage. C'est aussi pour ça que l'appui donne LOW.
- **Anti-rebond avec `millis()`** : le contact du bouton rebondit pendant quelques
  ms. Avec `millis()` au lieu de `delay()`, le programme ne se bloque jamais, ce qui
  sera indispensable pour le jeu.
- **Calibration et zone morte du joystick** : le centre réel est vers 1930 et pas
  2048, et sans zone morte le bruit de l'ADC ferait bouger le jeu tout seul.
- **Mesure crête à crête pour le micro** : la valeur instantanée d'une onde sonore
  ne représente pas le volume.
- **D4 et D6 pour les capteurs** : ce sont les seules broches libres avec le brochage
  de la console, ça évite de recâbler la mallette.
- **Fermer TelePlot avant de téléverser** : le port COM ne peut être ouvert que par
  un seul programme à la fois.
